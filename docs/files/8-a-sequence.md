## 二、从直觉到原理

### 1. 连续存储 vs 节点存储

**直觉**：数组像一排连号的座位，知道第一个座位和编号就能直接走过去；链表像寻宝游戏，每张纸条写着下一张在哪。

**原理**：
- 数组元素在内存里首尾相接，第 i 个元素地址 = 起始地址 + i × 元素大小，所以随机访问是 O(1)。连续内存还让 CPU 缓存一次能预取一整块，顺序遍历非常快。
- 链表每个节点单独分配，节点里存数据和指向下一个节点的指针。访问第 i 个要从头走 i 步，是 O(n)；而且节点散落在堆上，遍历时容易缓存未命中。

```c
int a[4] = {10, 20, 30, 40};
// a[2] 的地址 = &a[0] + 2 * sizeof(int)，一步算出

struct Node { int val; struct Node *next; };
// 找第 2 个：p = head; p = p->next; p = p->next;  要一步步跳
```

### 2. 索引和指针操作

- 数组用**索引**操作：在中间插入要把后面的元素整体后移，O(n)；在尾部追加通常 O(1)。
- 链表用**指针**操作：已经拿到某个节点时，在它后面插入只需改两个指针，O(1)。

```c
// 在节点 p 之后插入 q
q->next = p->next;
p->next = q;      // 顺序反了就会丢掉后半条链
```

**栈**（后进先出）和**队列**（先进先出）是对这两种存储的「限制用法」：栈只在一端进出，用数组尾部实现最自然；队列一端进一端出，用数组实现时如果每次出队都把元素前移会是 O(n)，于是有了**环形队列**：用 head、tail 两个下标在固定数组上「绕圈」。

```python
class RingQueue:
    def __init__(self, cap):
        self.buf = [None] * cap
        self.cap, self.head, self.size = cap, 0, 0

    def push(self, x):
        if self.size == self.cap:
            raise OverflowError("full")
        tail = (self.head + self.size) % self.cap   # 绕回
        self.buf[tail] = x
        self.size += 1

    def pop(self):
        if self.size == 0:
            raise IndexError("empty")
        x = self.buf[self.head]
        self.head = (self.head + 1) % self.cap
        self.size -= 1
        return x
```

这里用额外的 `size` 区分空和满。只用 head、tail 时 `head == tail` 既可能是空也可能是满，常见解法是：多记一个计数，或者故意空出一个槽位（tail 的下一个是 head 就算满）。

### 3. 容量增长与迭代器失效

动态数组（C++ `std::vector`、Go slice、Python list）底层是数组，满了就申请一块更大的内存（常见按 1.5 倍或 2 倍增长），把旧元素搬过去。单次扩容是 O(n)，但按倍数增长时，平均到每次追加是**均摊 O(1)**。

代价是：扩容后旧内存被释放，之前拿到的指针、引用、迭代器全部**失效**。

```cpp
std::vector<int> v = {1, 2, 3};
int* p = &v[0];
v.push_back(4);      // 可能触发扩容
// *p 此时可能是悬空指针，未定义行为
```

Go 里同样的坑：`append` 超过容量后返回的是新底层数组，旧 slice 和新 slice 不再共享数据。后台场景中，如果你已知一批推送任务大约有多少条，提前 `reserve` / `make([]T, 0, n)` 能避免反复扩容。

## 三、常见误区和设计权衡

- **误区：「链表插入是 O(1)」**。前提是**已经找到位置**。如果要先按下标或按值查找插入点，查找本身就是 O(n)。
- **误区：只看渐近复杂度**。链表理论上中间插入更便宜，但节点分散导致缓存不友好，在中小规模数据上数组往往整体更快，要用上一课的实验方法实测。
- **误区：扩容后继续用旧指针/迭代器**。见上一节。
- **权衡：节点稳定性 vs 缓存友好性**。链表节点地址不随插入删除改变，别处持有的指针一直有效（适合做 LRU 这类需要「拿着节点直接摘除」的结构）；数组缓存友好但扩容和中间插入会移动元素。两者常需取舍。

## 五、自测题

**1. 已知链表中某个节点的指针，在它后面插入新节点是什么复杂度？如果只知道要插入到第 k 个位置呢？**
答：前者 O(1)，只改两个指针。后者要先从头走 k 步找到位置，是 O(k)，最坏 O(n)。

**2. 用 head、tail 两个下标实现的环形队列，`head == tail` 有什么问题？怎么解决？**
答：空和满时都会出现 head == tail，无法区分。可以多维护一个元素计数 size，或者空出一个槽位，规定 `(tail + 1) % cap == head` 时为满。

**3. 下面代码有什么问题？**
```cpp
std::vector<int> v(3);
auto it = v.begin();
for (int i = 0; i < 100; ++i) v.push_back(i);
std::cout << *it;
```
答：`push_back` 多次超出容量会触发扩容，底层内存被重新分配，`it` 失效，解引用是未定义行为。应在插入完成后再取迭代器，或提前 `reserve`。
