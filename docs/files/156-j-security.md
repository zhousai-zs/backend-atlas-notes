> 节点摘要：从资产、信任边界和攻击路径定义验证、授权与审计，而非只检查输入格式。身份认证、资源授权与输入校验分别处理不同问题，服务端必须独立执行。

## 导读

前面几课关注交付与发布。诊断接口往往同样暴露在网络上：一旦把调用者输入直接变成出站 URL 或 shell 参数，未授权请求也可能触发副作用，错误页还可能把密钥和堆栈送出去。

教学假设：内容后台有一个诊断 HTTP 接口，用于按主机探测或拉取状态。以下路径、令牌和缺陷均为教学设计，不代表腾讯或微信内部实现。损坏模式会记录 SSRF 与命令拼接意图，但不会真的访问链路本地地址或执行攻击者命令。`is_live_network_ssrf=false`。

## 学习目标

1. 解释认证与授权及适用边界
2. 独立完成实践：为诊断 HTTP 接口绘制信任边界，阻止任意 URL 与 shell 参数。

## 为什么后端要懂

节点给出的理由是「保护 RPC、管理接口和运维工具。」这类接口权限高、输入灵活，一旦信任边界画错，就会从「排障工具」变成攻击跳板。

## 核心知识点

### 1. 认证与授权

**原理。** 认证回答「调用者是谁」，授权回答「这个身份能做什么」。OWASP REST Security Cheat Sheet 把 REST 资源视为由 URI 标识的对象，并强调对动作与表示的约束。有登录或持有某个令牌，并不等于拥有所有诊断能力。

**直觉。** 先确认身份，再按最小权限决定能否触发 fetch 或 ping；未通过认证的请求不应进入会有副作用的代码路径。

**实践对照。** 固定模式在缺少 `Authorization: Bearer …` 时返回 401，副作用计数保持 0。损坏模式则在未授权时已经记录了 2 次副作用，并在错误体中泄漏教学密钥。

### 2. SSRF 与命令注入

**原理。** 若接口把用户提供的 URL 直接取出站请求，攻击者可以转向链路本地、云元数据或内部网。若把用户字符串拼进 shell，分号和管道会变成新命令。修复方法是允许名单、合法字符校验，以及不经过 shell 的调用。

**实践对照。** 损坏模式对 `http://169.254.169.254/latest/meta-data/` 和 `file:///etc/passwd` 返回 200，并承认 `would_ssrf=true`；对 `8.8.8.8;id` 返回拼接后的 `ping -c 1 8.8.8.8;id`。固定模式对上述输入一律 400，允许名单中的 `example.invalid` 与主机名 `cache-1.internal` 才返回 200，且 ping 不走 shell。本课没有真正连接 169.254.169.254。

### 3. 密钥轮换与最小权限

**原理。** 错误响应、日志和调试字段都可能把密钥带出进程。最小权限意味着诊断接口只开放必要的主机与方法；密钥即使存在于环境变量，也不应出现在 401/400 的正文里。轮换则是泄露或人员变更后的后续动作，本课只演示「不泄漏」，没有实施轮换流程。

**实践对照。** 固定模式的错误体只有 `request_rejected` 与状态码，JSON 中不含教学密钥，也不含 Traceback。损坏模式的 401 会带上 `secret` 与堆栈字段。

## 常见误区

1. **有登录即认为拥有所有资源权限。** 节点原句即此。本课即便持有令牌，也不允许任意 URL 或 shell 字符；认证只是授权的前提。
2. **认为没有真正执行命令，拼接就没有风险。** 损坏模式虽未调用 shell，但已经组成了含 `;id` 的命令串。只要下一次有人把该字符串交给 shell，注入就完成了。

## 设计权衡

节点原句是「严格边界可能降低灵活性，需要清晰的授权模型。」允许名单会挡住临时排查未登记主机的需求，换来的是诊断接口不能再做跳板。若确实需要更宽的探测，应走单独的、有审计的授权路径，而不是把任意 URL 留给默认接口。

实践目录为 `practice156/`，需要 Python 3。本次为 CPython 3.13.5。

```bash

```

脚本先跑损坏模式并确认缺陷被抓住，再跑固定模式核验收。成功最后一行为 `ALL_CHECKS_PASSED`。

本次官方实践目录：损坏模式未授权副作用为 2 且泄漏密钥，SSRF 与命令拼接返回 200；固定模式未授权副作用为 0、错误不泄漏，非法 URL 与 shell 参数返回 400。信任边界见 `reports/boundary.json`。

两项验收是「未授权请求不会触发副作用」以及「错误响应不泄漏密钥或堆栈」。它们只在固定模式成立；损坏模式必须被测试抓住。

## 自测题

1. **认证通过后，为什么仍要拦截任意 URL？** 认证只说明调用者是谁；任意 URL 会越过信任边界，形成 SSRF。本课持有令牌也不能访问链路本地或 `file://`。
2. **未授权请求返回 401 就够了吗？** 还要确认没有副作用。损坏模式在返回 401 之前已经记账 2 次。
3. **错误页里附上堆栈是否更方便排障？** 方便，但会泄漏实现细节乃至密钥。固定模式把对外错误收成 `request_rejected`，详细信息应留在受控日志里。
