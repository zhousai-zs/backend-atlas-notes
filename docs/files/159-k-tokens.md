# 第 159/208 课：Token、窗口与生成预算

> 序号 159/208 · id `k-tokens` · 领域 K · 阶段 1 · 难度 基础 · 子类 模型接口与输出
> 前置：[`k-transformer`](https://zhousai-zs.github.io/backend-atlas-notes/lessons/158.html)
> 节点摘要：不同编码器把同一段文本切成不同数量的 token；预算不能按字符数一刀切。

## 导读

计费、截断、上下文窗口都按 token，不按字符。同一段中文日志，换一套编码器，数目可以差出一大截。本课用**官方 tiktoken 0.14.0** 在本机实测，而不是口头估算。

教学假设：要把一份中文故障日志和一段 C++ 放进有限窗口，必须留下错误栈和任务约束。以下日志是教学样本。`is_live_model=false`：没有调用生成模型，只做分词与截断策略。

## 学习目标

1. 解释编码器差异及适用边界
2. 独立完成实践：统计中文日志和 C++ 文件的 token 数，制定截断与摘要策略。

## 为什么后端要懂

按字符数给所有模型估预算，会在一种编码器下超窗、在另一种下浪费。截断若先丢掉栈和约束，省下的预算没有价值。

## 核心知识点

### 1. 编码器差异

**直觉。** Tokenizer 是模型的「字母表」。不存在一种所有模型共享的切法。

**原理。** 2026-11-15 抓取官方仓库与 PyPI：`https://github.com/openai/tiktoken`、README 与 `https://pypi.org/pypi/tiktoken/json`（Date 均为 2026-11-15 22:58:54–55 CST）。当日 PyPI 当前发布为 tiktoken 0.14.0，本机安装并使用该版本。用同一份 529 字符（669 字节）的中文日志：

| 编码 | 日志 token | 日志 token/字符 | 同目录 `cache.cpp` token（413 字符） |
| --- | --- | --- | --- |
| cl100k_base | 291 | 0.5501 | 129 |
| o200k_base | 267 | 0.5047 | 131 |
| p50k_base | 377 | 0.7127 | 167 |

日志在 p50k 下比 o200k 多 110 个 token。节点验收「不使用字符数直接估算所有模型预算」由此成立：529 个字符对应 267、291 或 377，没有统一乘数。C++ 的字符/token 比又和中文日志不同。

**适用边界。** tiktoken 覆盖的是它所实现的那些 OpenAI 编码。其他厂商的编码器要用它们自己的工具测量，不能把上表系数搬过去。本课没有测量那些编码器。

### 2. 输入/输出预算

**直觉。** 窗口要同时装下系统提示、检索片段、用户输入和预留给输出的长度。只看「输入多长」会在生成到一半时撞墙。

**原理。** 输入 token 与输出 token 通常分开计价，也分开占用上下文。本课没有实调计费接口，只在本地用输入长度做截断预算，并明确：输出预留没有在本次实验里向模型要完成长度。

### 3. 截断与上下文上限

**直觉。** 超窗时不能从头或从尾一刀切。错误栈和任务约束往往是最短的可行动信息。

**实践对照。** 策略把栈和约束视为必留。在 cl100k、预算 80 的教学设置下，必留部分本身就有 112 个 token，大于 80。结果是：保留 112，丢掉 4 行非必留日志，并记录 `clip_kept_stack_and_constraints=true`、`required_tokens=112`、`budget=80`。这里的教训不是「神奇地把 112 塞进 80」，而是：**当必留已经超过预算，策略应显式失败或扩大窗口，而不是默默删掉栈。** 本课选择「始终保留必留，即使超过软预算」，避免为了数字好看删掉证据。

## 常见误区

- 以为所有模型共享同一种 tokenizer。
- 用字符数或英文「1 token ≈ 4 字符」去估中文日志。
- 截断时先删堆栈，留下大段重复的环境说明。

## 设计权衡

截断节省成本，但可能删除决定性证据。本课宁可让必留超过软预算并被记录，也不自动砍栈。更大的窗口更安全，也更贵。

## 自测题

**1. 为什么同一段中文日志会有 267 和 377 两种计数？**

答案：o200k_base 与 p50k_base 的词表和切分规则不同。必须针对目标模型使用对应编码器。

**2. 必留 112、预算 80，本课为什么不强制输出 ≤80？**

答案：若为了满足 80 而切开错误栈，任务反而不可做。策略选择保留约束并记录超预算，让调用方去加窗或换模型。

**3. 本课能直接给出某个新模型的账单吗？**

答案：不能。没有调用计费 API，也没有该模型的官方单价实验。只能给出 token 数量，单价需查阅当日官方定价页。
