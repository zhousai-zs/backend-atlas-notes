第 157/208 课：后台工程师的机器学习基础

序号 157/208 · id k-ml · 领域 K · 阶段 1 · 难度 基础 · 子类 模型能力与表示 前置：无（K 领域起始课） 节点摘要：模型从数据中拟合统计关系，训练、验证与测试划分用于估计泛化，不能把测试集反复用于调参。

导读

J 领域把服务交到线上。从本课开始进入模型能力：先分清训练与推理、以及「验证集很高」并不等于线上有效。泄漏字段会让离线分数看起来完美，一旦线上不再提供该字段，分数就会崩掉。

教学假设：用 40 条教学故障摘要做基础设施/应用二分类。以下文本、标签和泄漏字段均为教学设计，不代表腾讯或微信内部实现或线上模型。训练器是 NumPy 实现的逻辑回归，is_live_model=false，没有调用远程模型 API。

学习目标

  1. 解释监督学习与损失及适用边界
  2. 独立完成实践：用小型文本分类模型做训练/验证划分，加入泄漏字段观察虚假高分。

为什么后端要懂

节点给出的理由是「理解模型服务质量与数据分布的关系。」服务是否好用，取决于线上数据是否仍与训练/验证时同分布；泄漏和漂移会让离线指标失效。

核心知识点

1. 监督学习与损失

原理。 监督学习用带标签的样本拟合从输入到标签的映射。Google Machine Learning Crash Course 在 2026-11-15 的课程首页仍以线性回归、逻辑回归和分类等模块组织，并强调损失与梯度下降等基础。逻辑回归估计某一结果的概率。损失（本课用对数损失）衡量预测与标签的偏差；训练通过更新参数降低训练集损失。

直觉。 训练是在已知答案的数据上改权重；推理只使用冻结的权重，不应再看见标签。

实践对照。 40 条样本按 28/12 划分。干净特征下验证准确率 0.9167、对数损失 0.3262；训练准确率 1.0。NumPy 2.5.4。这是极小教学拟合，不能外推到生产模型质量。

2. 过拟合与数据泄漏

原理。 同日抓取的模块 Datasets, generalization, and overfitting 把学习目标列为：解释训练集、验证集和测试集，识别数据划分中的潜在问题，并解释过拟合及其可能原因。该页是目标提纲，没有给出「泄漏」一词的正式定义。本课把泄漏实现为：把真实类别标记作为额外特征同时放入训练和验证，这是划分/特征问题的一个具体例子，而不是该页的原文字句。

直觉。 如果验证时也能看到「这就是标准答案」的字段，模型不必学习文本，分数却会接近满分。

实践对照。 加入泄漏类别标记后，验证准确率升到 1.0，损失降到 0.1525。同一批样本若在服务侧把泄漏标记取反（分布漂移），准确率变为 0.0。离线「完美」因此不能说明上线有效。

3. 分布漂移

原理。 当线上特征、用户或标签过程与离线数据不同，原来的分数就失去参照。本课用「泄漏标记在线上不再可靠」模拟其中一种漂移，而不是完整的数据监控系统。

实践对照。 duties 记录：训练更新权重，推理使用冻结权重且不应看到标签。漂移集只做推理，不再训练。

常见误区

  1. 把模型输出当作确定性事实。 节点原句即此。即便干净模型在本批验证上达到 0.9167，输出仍是概率阈值后的类别，遇到新写法或新故障类型都会错。泄漏模型的 1.0 更不能当成事实。
  2. 只看验证准确率、不检查特征是否在线上可获得。 泄漏字段只存在于离线表时，分数没有部署意义。

设计权衡

节点原句是「更复杂模型未必胜过质量更好的数据。」本课甚至没有换模型，只是去掉或加入一个泄漏字段，分数就从 0.9167 变成 1.0 再掉到 0.0。先检查标签和特征是否可在线上复现，通常比急着加深网络更有用。

动手实践

实践目录为 practice157/，需要 Python 3 和 NumPy。本次为 CPython 3.13.5、NumPy 2.5.4。不要把该脚本说成已部署的分类服务或实调的大模型。

bash test.sh
cat results.json

两项验收是「解释高离线分数为何未必上线有效」以及「能描述训练与推理职责」。前者对应 1.0 的泄漏验证分在标记取反后变为 0.0；后者对应 duties 中的职责划分。

自测题

  1. 验证集准确率 1.0 为什么还可能上线失败？ 若该分数依赖线上不存在或会改变的泄漏字段，服务分布一切换，分数就会掉。本课取反后准确率为 0.0。
  2. 训练和推理有何不同？ 训练根据标签更新权重；推理只使用冻结权重，不应再读标签来「改答案」。
  3. 模型给出类别，能否当成确定性事实？ 不能。输出是按阈值做的判定，对新分布没有保证。
